1. BACKEND API ENDPOINTS FOR FRONTEND INTEGRATION
--------------------------------------------------------------------------------

Base URL: http://localhost:5000/api
(In Vite development, /api is proxied to http://localhost:5000/api)

--------------------------------------------------------------------------------
A. Catalog Endpoints
--------------------------------------------------------------------------------

1. GET /api/catalog/flights
   - Purpose: Fetch available arrival flights to populate the flight dropdown.
   - Query Parameters (Optional):
       * to: Filter by arrival airport code (e.g., ?to=NRT)
       * from: Filter by departure airport code (e.g., ?from=BLR)
       * date: Filter by arrival date (e.g., ?date=2027-04-10)
       * all: Set to "true" to include flights to India; by default only arrival
              flights (NRT, HND, KIX, DXB, AUH) are returned.
   - Response Format:
       {
         "success": true,
         "count": 240,
         "data": [
           {
             "flight_id": "FL-401",
             "airline": "AirVeda",
             "flight_number": "AV 520",
             "from": "BLR",
             "to": "NRT",
             "departure_local": "2027-04-09T23:50:00",
             "arrival_local": "2027-04-10T10:30:00",
             "stops": 0,
             "duration_minutes": 430,
             "price_per_seat": { "amount": 25200, "currency": "INR" },
             "seats_left": 9,
             "cabin": "ECONOMY"
           },
           ...
         ]
       }

2. GET /api/catalog/hotels
   - Purpose: Fetch destination hotels to populate the hotel dropdown.
   - Query Parameters (Optional):
       * city: Filter by city name (e.g., ?city=Tokyo)
       * area: Filter by area name (e.g., ?area=Ueno)
   - Response Format:
       {
         "success": true,
         "count": 49,
         "data": [
           {
             "hotel_id": "HTL-TYO-004",
             "name": "Ueno Garden Inn",
             "aliases": [],
             "city": "Tokyo",
             "area": "Ueno",
             "lat": 35.712,
             "lng": 139.7728,
             "rating": 7.9,
             "stars": 3,
             "check_in_from": "15:00",
             "check_out_until": "11:00",
             "family_friendly": true
           },
           ...
         ]
       }

3. GET /api/catalog/airports
   - Purpose: Fetch airport data and their served cities (used for R1 validation).
   - Response Format:
       {
         "success": true,
         "count": 10,
         "data": [
           {
             "code": "NRT",
             "name": "Narita International Airport",
             "city": "Tokyo",
             "country": "JP",
             "timezone": "Asia/Tokyo",
             "lat": 35.772,
             "lng": 140.3929,
             "serves_cities": ["Tokyo"]
           },
           ...
         ]
       }

4. GET /api/catalog/suppliers
   - Purpose: Fetch taxi suppliers (for display / reference in supplier cards).
   - Response Format:
       {
         "success": true,
         "count": 11,
         "data": [
           {
             "company_id": "TX-JP-01",
             "name": "Sakura Cabs",
             "airports": ["NRT", "HND"],
             "service_from": "06:00",
             "service_until": "23:00",
             "rating": 4.4,
             "vehicles": [...]
           },
           ...
         ]
       }

--------------------------------------------------------------------------------
B. Route & Price Range Endpoints
--------------------------------------------------------------------------------

1. GET /api/routes/price-range?flightId={flightId}&hotelId={hotelId}
   - Purpose: Triggered when user selects both a flight and a hotel.
              Checks airport-city compatibility (R1) and returns authoritative
              price range (R3) and drive duration.
   - Query Parameters (Required):
       * flightId: e.g., "FL-401"
       * hotelId: e.g., "HTL-TYO-004"
   - Success Response (200 OK):
       {
         "success": true,
         "data": {
           "minPrice": 10200,
           "maxPrice": 16800,
           "price_min_inr": 10200,
           "price_max_inr": 16800,
           "currency": "INR",
           "route": {
             "airport": "NRT",
             "city": "Tokyo",
             "area": "Ueno",
             "distance_km": 73.3,
             "drive_minutes": 90
           }
         }
       }
   - Error Response (400 Bad Request - e.g. R1 Incompatibility):
       {
         "success": false,
         "error": "Airport NRT (Tokyo) does not serve hotel city Osaka. Serves: [Tokyo]"
       }

--------------------------------------------------------------------------------
C. Ride Request Endpoints
--------------------------------------------------------------------------------

1. POST /api/ride-requests
   - Purpose: Submit a new ride request from the traveler form.
   - Headers: { "Content-Type": "application/json" }
   - Request Body:
       {
         "travelerName": "Menon family",           // Optional, default "Traveler"
         "flightId": "FL-401",                     // Required (R1)
         "hotelId": "HTL-TYO-004",                 // Required (R1)
         "adults": 2,                              // Required, integer >= 1 (R1)
         "childAges": [6],                         // Required array, ages 0-17 (R1)
         "largeBags": 3,                           // Optional, integer >= 0
         "smallBags": 2,                           // Optional, integer >= 0
         "pickupTime": "2027-04-10T11:30:00",      // Optional, defaults to landing + 60m (R2)
         "travelerPrice": 12000,                   // Required, between min and max (R3)
         "carType": "SEDAN"                        // Optional: null | HATCHBACK | SEDAN | SUV | BUS
       }
   - Success Response (201 Created):
       {
         "success": true,
         "message": "Ride request created successfully",
         "data": {
           "id": "REQ-10457637",
           "travelerName": "Menon family",
           "flightId": "FL-401",
           "hotelId": "HTL-TYO-004",
           "adults": 2,
           "childAges": [6],
           "largeBags": 3,
           "smallBags": 2,
           "pickupTime": "2027-04-10T11:30:00",
           "carType": "SEDAN",
           "travelerPrice": 12000,
           "status": "open",
           "flight": { ... },
           "hotel": { ... },
           "route": { ... }
         }
       }
   - Error Response (400 Bad Request):
       {
         "success": false,
         "error": "R3 Validation Error: Proposed price ₹9,000 is outside the allowed route range of ₹10,200 – ₹16,800",
         "errors": [ ... ]
       }

2. GET /api/ride-requests
   - Purpose: Retrieve list of all requests for traveler dashboard.
   - Query Parameters (Optional):
       * status: Filter by status (e.g., ?status=open)
   - Response Format:
       {
         "success": true,
         "count": 4,
         "data": [ ...requests with enriched flight, hotel & route metadata... ]
       }

3. GET /api/ride-requests/:id
   - Purpose: Retrieve a single request by its unique ID (e.g. /api/ride-requests/REQ-0001).

3. VALIDATION RULES IMPLEMENTATION SUMMARY (R1, R2, R3)
================================================================================

Rule R1 (Flight, Hotel & Passenger Validation):
- Flight must exist in flights.json (only flights landing in NRT, HND, KIX, DXB, AUH).
- Hotel must exist in hotels.json.
- Flight arrival airport must serve hotel's city:
  * NRT, HND serve Tokyo
  * KIX serves Osaka, Kyoto
  * DXB serves Dubai, Abu Dhabi
  * AUH serves Abu Dhabi
- At least 1 adult required (adults >= 1).
- Each child age must be an integer between 0 and 17.

Rule R2 (Pickup Time Validation):
- Earliest pickup time = flight arrival_local + 60 minutes.
- If traveler omits pickup time, arrival_local + 60m is applied automatically.
- Comparing dates strictly in airport local wall-clock time without timezone skew.

Rule R3 (Traveler Price Validation):
- Authoritative bounds from routes.json (airport + city + area):
  price_min_inr <= traveler_price <= price_max_inr.
- Prices below min or above max are rejected with a clear descriptive message.
